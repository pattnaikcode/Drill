How the YAML works

    
YAML is a plain-text format of key: value pairs. Indentation shows what belongs to what, and a line starting with - is one item in a list. The builder writes it for you; this is what each part means.

    

      
The system
id: exchange
system: Equity exchange trading platform
id is the short name use cases refer to; system is the name people see.

      
The clock
clock:
  start: "14:30"
  cutoff: "15:30"
  cutoff_label: Clearing cut-off
The simulated window. Faults happen between start and cut-off; the drill is scored against the cut-off. Times are in quotes because a bare 14:30 confuses YAML.

      
Business impact
business:
  unit_name: orders
  avg_notional: 0.04
  kpis:
    - {label: Trades not with clearing,
       at: clearing, cutoff: true}
A KPI counts work sent in but not yet past a component. avg_notional turns counts into money. The KPI marked cutoff: true decides whether the deadline was met.

      
Components
components:
  - {id: fix_gateway, type: service,
     name: FIX Order Gateway,
     capacity_per_min: 2700, instances: 3}
One line per component, written in { } braces. type decides how it behaves, which faults it can have and which actions fix it. Each type has its own settings, and the forms show them.

      
Dependencies
  - {id: risk, type: service, ...,
     uses: [instrument_master]}
  - {id: issuer_2, type: issuer, ...,
     feeds: instrument_master}
Databases and reference data are not in the flow: a service lists them in uses. Issuers publish into reference data with feeds. Square brackets [ ] are a list.

      
The flow
flow:
  - broker_a -> fix_gateway
  - fix_gateway -> risk -> matching
  - matching -> md_publisher
Each line is a path work travels along. A component can appear on several lines: five brokers into one gateway (fan-in), or matching out to several systems (fan-out). Every flow starts at a participant.

      
Alert rules
alerts:
  - {name: Gateway queue building,
     on: fix_gateway, metric: backlog,
     above: 1500, severity: P2}
Fires when the metric stays past the threshold for one simulated minute. Use above or below. The metric must exist for that component type.

      
Flow diagram
diagram:
  groups:
    - {label: Members, ids: [broker_a, mm_1]}
  steps:
    - {from: broker_a, to: fix_gateway,
       text: Brokers send orders over FIX.}
Groups draw a labelled box around components. Steps add numbered badges to links and a numbered list under the diagram. Optional place fixes positions as [column, row].
